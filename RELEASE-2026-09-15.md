# RideSafe — Excel imports, unread messages and driver GPS

The source package preserves every prior application module. Run `npm run check`
from the project root before uploading to GitHub, then deploy using the same
environment values for Neon PostgreSQL and Upstash Redis used by the app.

## Changes

- Student, academic calendar and attendance `.xlsx` templates now import with
  the server parser. Normal Excel workbooks and `.csv` continue to work.
- Student import matches the school's `Student ID` and updates that record on
  later uploads. New IDs create students; duplicate IDs within a single file
  are reported. Missing bus, route, parent and stop assignments appear as row
  warnings so a pending student cannot be mistaken for a trip-ready student.
- Attendance import reports unmatched historical trip/student rows and existing
  duplicate records. The imported date and the live trip must match, with the
  same service, bus, route and assigned student; it never invents a trip or
  overwrites an attendance confirmed by the bus crew. Export includes the
  service and Student ID for reliable future imports.
- Calendar imports require each event's `Title`/`Event Name` and
  `Start date`/`Date`; accept Excel-formatted dates, DD/MM/YYYY and YYYY-MM-DD.
  School-scoped published events are made visible to that school's parents.
- Chats show a highlighted row and unread dot for each correspondent. Staff
  sharing one school chat have independent unread receipts; opening the
  Messages section alone does not erase those unread markers.
- Student deletion is permanent when no attendance, parent confirmation or
  transport issue references that student. For historically referenced students
  the API returns a clear conflict: deleting those records too would require a
  separate retention/deletion decision.
- Mobile GPS is accepted only from the assigned bus driver during an active
  trip; a maintainer no longer overwrites the driver's coordinates. A trip
  requires an active assigned driver. Mobile sharing stops when the trip ends.
- The repository explicitly permits the six reviewed Prisma/Next dependency
  install scripts required for reproducible production builds with modern npm.
- Removed a leftover workbook inspection dump from the publicly served
  `templates` folder; actual import templates remain intact.

## Arrival horn in production

The server deduplicates the notification for a student's next assigned stop
when fresh GPS indicates an ETA of 1–5 minutes. The parent's open browser can
play the horn three times after the parent enables audio with a tap. Browsers
cannot guarantee background or locked-phone audio; location permission, route
stop coordinates, push permission and a continuously running GPS source are
also prerequisites. A Vercel web deployment does not run the project's
continuous tracking worker: host it separately for unattended hardware polling.

## Safe release

1. Upload the **complete** project folder to GitHub, including `next-env.d.ts`,
   `SOURCE-MANIFEST.json`, the new source and tests. Do not commit real `.env`.
2. On Vercel use Next.js, Install Command `npm ci`, Build Command
   `npm run build`, and leave Output Directory blank.
3. Configure `DATABASE_URL`, `REDIS_URL`, `JWT_SECRET`, `APP_URL`, the VAPID
   public/private keys and `TRACKING_WORKER_SECRET`. Use the site's exact HTTPS
   origin for `APP_URL` to avoid cross-origin write rejections.
4. Apply committed migrations to production with pinned Prisma 5.22.0
   (`npx prisma@5.22.0 migrate deploy`) before testing logins. This release has
   no new database migration.
5. Recheck import against a real school with assigned bus/route/stops/parent,
   and verify the five-minute notification on a real trip with driver GPS.
